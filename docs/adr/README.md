# 架構決策紀錄（ADR）

這個目錄記錄 Kairos／Pulse 需要使用者核定的架構決策：每份 ADR 說明問題的脈絡、考慮過的方案、建議的決策與後果。規格文件（`crates/kairos-proto/*.md`、`kairos/*.md`）描述「現在怎麼做」；ADR 描述「為什麼這樣決定」。

## 狀態

- **提議**：已寫出建議，等使用者核定。尚未實作，內容可能修改。
- **已核定**：使用者同意，照此實作；之後要改變時另寫一份 ADR 取代它。
- **已取代**：被較新的 ADR 取代（註明編號）。

## 審查與修訂

三份 ADR 的初稿（commit `4eb7086`）都經過外部審查（codex，唯讀、回到程式碼核對事實），結論都是「修改後核定」。審查報告在 [`reviews/`](reviews/)；各 ADR 已依審查修訂，文末的「修訂紀錄」逐項列出每個意見的處置（採納／部分採納／不採納與理由）。修訂後的版本沒有再次送審；使用者於 2026-11-13 核定三份 ADR（待決事項除另有註明外皆採文內建議；0002 的 U8 實作範圍仍待選定）。核定後的實作尚未開始，除了 0003 的立即修正項與階段 0b 已排入 0.10.0。

0002 的待決事項 U4（推送的時段名稱）另有兩份研究（[codex](reviews/0002-u4-naming-codex.md)、[grok](reviews/0002-u4-naming-grok.md)），都建議推送側改稱「升級時段」、告警側維持「維護時段」、英文識別字不動；使用者已於 2026-11-12 決定採用「升級時段」。

## 三份 ADR 之間的關係

- 0003 把回滾的信任規則寫成與平台無關的不變條件（INV-1～INV-11），並回答 0001 提出的 Q1～Q6；0001 的「前一槽」套用同一套規則。修訂後 0001 已採納 0003 的建議（選槽改用單調遞增的 generation、種子也走試用、明寫 Windows 沒有特權分離）；金鑰顯式撤銷如何回報給 Kairos 以 0003 定稿為準。
- 0003 的「立即修正項」：輔助程式採信 `request.json` 的缺口影響已發佈的 0.9.0。使用者已決定只在 0.10.0 修正、不另出 0.9.1、不發安全公告（0.9.0 尚無正式使用者）。
- 0002 不是獨立的：0001 的 `slot` 安裝方式與 0003 的 `rollback_bundle`／本機封存會改變資格預覽、「無法自動回滾」與版本庫畫面的統計，0002 已留接點（原因代碼由資料驅動、台數與確認字串由伺服器計算）。
- 0001 另外列出現行 Windows 服務（0.8～0.10）的既有缺陷 X1～X4（服務失敗後的重啟次數與文件不符等），不待 ADR 核定即應處理。

## 撰寫方式

編號遞增、檔名 `NNNN-主題.md`。章節依序為：狀態、日期、決策者、脈絡、決策驅動因素、考慮的方案、決策、後果、實作計畫、待決事項、參考資料。事實主張標明是從程式碼確認、查證過的外部資料，還是推論。
