# 架構決策紀錄（ADR）

這個目錄記錄 Kairos／Pulse 需要使用者核定的架構決策：每份 ADR 說明問題的脈絡、考慮過的方案、建議的決策與後果。規格文件（`crates/kairos-proto/*.md`、`kairos/*.md`）描述「現在怎麼做」；ADR 描述「為什麼這樣決定」。

## 狀態

- **提議**：已寫出建議，等使用者核定。尚未實作，內容可能修改。
- **已核定**：使用者同意，照此實作；之後要改變時另寫一份 ADR 取代它。
- **已取代**：被較新的 ADR 取代（註明編號）。

## 索引

| 編號 | 主題 | 狀態 | 日期 |
|---|---|---|---|
| [0001](0001-windows-ota-upgrade.md) | Pulse 在 Windows 上的遠端升級採用類似 OTA 的機制（A/B 版本槽＋啟動器） | 提議 | 2026-11-12 |
| [0002](0002-rollout-console-design.md) | 升級推送的進階流程（雙人覆核、自訂批次、維護時段）在主控台上的設計補齊 | 提議 | 2026-11-12 |
| [0003](0003-rollback-bundle-trust.md) | 遠端升級的回滾檔（`rollback_bundle`）如何被信任 | 提議 | 2026-11-12 |

## 三份 ADR 之間的關係

- 0003 把回滾的信任規則寫成與平台無關的不變條件（INV-1～INV-11），並回答 0001 提出的 Q1～Q6；0001 的「前一槽」套用同一套規則。
- 0003 對 0001 提出四點修改建議（掃描時選哪一槽、種子切換是否走試用、Linux 本機紀錄的信任等級、Windows 沒有特權分離），**尚未併入 0001**，核定時一併決定。
- 0003 的「立即修正項」不待核定：其中輔助程式採信 `request.json` 的缺口影響已發佈的 0.9.0，修正排入 0.10.0。
- 0002 只涉及主控台與設計包，與另外兩份獨立。

## 撰寫方式

編號遞增、檔名 `NNNN-主題.md`。章節依序為：狀態、日期、決策者、脈絡、決策驅動因素、考慮的方案、決策、後果、實作計畫、待決事項、參考資料。事實主張標明是從程式碼確認、查證過的外部資料，還是推論。
